# Project overview
Это проект, который транслирует посты из Reddit в Telegram. С помощью веб интерфейса можно добавлять и удалять источники (Reddit subreddits), а также управлять теми, которые уже добавлены. Данные из источника сохраняются в очередь или список в базе данных, к этому списку/очереди можно подключить Telegram бот, его можно настраивать через веб интерфейс, например расписание публикаций. Пока посты находятся в очереди их нужно обработать: перевести на русский язык, суммаризировать длинный текст, изменить стилистику текста, замазывать водяные знаки в видео или в картинках и тд. После этого посты готовы к публикации в Telegram.

Для проекта потребуется:
- Next.js
- shadcn/ui
- Nest.js
- TypeScript
- Snoowrap

## Определения терминов
- **Секция источников**: Логическая группа, объединяющая один или несколько источников (например, сабреддиты), из которых собираются посты. Секция привязана к одной очереди, в которой хранятся посты, которые нужно обработать.
- **Источник**: Конкретный сабреддит или другой источник данных, из которого извлекаются посты для обработки и публикации.
- **Телеграм канал**: Канал в Telegram, куда транслируются обработанные посты из очереди.
- **Очередь необработанных постов**: Список постов, к которому привязана секция источников. К одной очереди необработанных постов привязана одна секция источников. Из одной очереди необработанных постов они обрабатываются и попадают в одну очередь обработанных постов.
- **Очередь обработанных постов**: Список постов, которые прошли обработку и готовы к публикации. К одной очереди необработанных постов привязано несколько очередей обработанных постов. К одной очереди обработанных постов может быть привязан один телеграм канал
- **Обработка постов**: Процесс подготовки постов к публикации, в котором могут быть использованы различные инструменты: перевод, суммаризацию, изменение стилистики, обработка изображений и видео и другие действия. Обработка постов происходит в отдельном сервисе, который запускается по расписанию и обрабатывает посты из очереди необработанных постов, помещая готовые посты в очередь обработанных постов. Для каждого телеграм канала можно настроить отдельную обработку постов.

# Core functionality
1. Видеть весь список секций источников и привязанных к ним telegram каналов
  1.1 Этот список должен быть сортируемым по названию секции источников, названию телеграм канала, по количеству постов в очереди, по количеству опубликованных постов
  1.2 Должна быть возможность поиска по названию секции источников, названию телеграм канала
  1.3 Должна быть возможность просматривать список групп секций источников и телеграм каналов
2. Добавлять новые секции источников и привязывать к ним telegram каналы
  2.1 На странице добавления новой секции источников нужно обязательно указать названия сабреддитов, к которым будет привязана секция. Название телеграм канала не обязательно, если не указать, то посты будут сохраняться в базе данных, но не будут транслироваться в телеграм канал
  2.2 К одной секции источников можно привязать один или несколько телеграм каналов. Для каждого телеграм канала можно настроить отдельную обработку постов
3. Секции источников могут быть сгруппированы пользователем в наборы, состоящие из нескольких секций источников, например по тематике
  3.1 Для создания набора нужно указать название набора и список секций источников, которые будут входить в него
  3.2 Наборы должны быть сортируемы по названию набора и по количеству постов в очереди
  3.3 Должна быть возможность поиска по названию набора
4. На странице отдельной секции источников видеть список постов, которые находятся в очереди на публикацию
5. На странице отдельной секции источников можно переходить на страницу отдельного телеграм канала и настраивать для него обработку постов или создавать новый телеграм канал
  5.1 Добавлять новые телеграм каналы и настраивать для них отдельную обработку постов
  5.2 Изменять настройки обработки постов для каждого телеграм канала
  5.3 Настраивать расписание публикаций для каждого телеграм канала
  5.4 Просматривать неопубликованные посты на странице отдельного телеграм канала и редактировать их
  5.5 Удалять телеграм каналы
6. Посты дожны быть уникальными в рамках одного телеграм канала, но могут повторяться в разных телеграм каналах

# Системная архитектура

## Компоненты системы и их взаимодействие:

### Reddit Fetcher
- Собирает посты из Reddit по настраиваемым критериям:
  * Top posts за день/неделю/месяц
  * Rising posts
  * Посты с определенным количеством upvotes
  * Посты за определенный временной период
- Сохраняет метаданные постов в Supabase для отслеживания статистики
- Использует BullMQ для создания задач на сбор постов по расписанию
- Обновляет статистику постов для возможности выбора наиболее популярных

### Post Processor
- Использует BullMQ для организации очередей обработки
- Реализует конвейерную обработку постов:
  1. Предварительная обработка (извлечение текста, медиа)
  2. Перевод (DeepL API)
  3. Обработка медиа (удаление водяных знаков, оптимизация)
  4. Стилистическая обработка (OpenAI API)
  5. Форматирование для Telegram
- Каждый этап конвейера опционален и настраивается для каждого канала
- Новые инструменты обработки могут быть добавлены как отдельные этапы конвейера

### Telegram Publisher
- Работает только с промодерированными постами
- Использует BullMQ для управления очередью публикаций
- Поддерживает гибкое расписание публикаций для каждого канала

### Модерация
- AI-агент на базе OpenAI API для автоматической модерации:
  * Анализ содержимого на соответствие тематике
  * Проверка тональности и стиля
  * Выявление нежелательного контента
- Веб-интерфейс для ручной модерации
- Настраиваемые правила автомодерации для каждого канала

## Технологический стек

### Backend:
- Nest.js (основной фреймворк)
- Supabase (база данных и аутентификация)
- BullMQ + Redis (управление очередями)
- OpenAI API (модерация и обработка текста)
- DeepL API (переводы)
- Snoowrap (Reddit API клиент)
- Telegraf (Telegram Bot API клиент)

### Frontend:
- Next.js
- shadcn/ui
- Supabase Client

### Инфраструктура:
- Vercel (фронтенд)
- Railway или Render (бэкенд)
- Supabase Cloud
- Upstash Redis (для BullMQ)

## Схема потоков данных:
Reddit API -> Reddit Fetcher -> BullMQ Queue -> Post Processor -> Supabase -> 
AI Модерация -> BullMQ Publication Queue -> Telegram Publisher -> Telegram API
